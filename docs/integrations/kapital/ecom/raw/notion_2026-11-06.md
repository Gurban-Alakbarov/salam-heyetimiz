## Authentication

All operations require BasicAuth-formatted header for authentication. This header contains the merchant's username and password, which are encoded in base64. This is a more secure way to authenticate merchants, as it prevents the username and password from being sent in plain text.

More information about BasicAuth :

https://www.twilio.com/docs/glossary/what-is-basic-authentication

## Operation Flow

### Transaction flow (Common payment)

- Send create order request (Order_SMS). If success response go to step 2

- Redirect to URL with values from Create Order response (point 1): Url Sample: 

{{order.hppUrl}}/flex?id={{order.id}}&password={{order.password}}

- Redirect client with several (described below) transaction fields to redirect (callback ) url after transaction completion on PC (Processing center side). Transaction flow completed.Callback url sample:{{callback.url}}?ID=1234&STATUS=FullyPaid

Note that STATUS parameter value can be temporary. So you have to verify transaction status using a Transaction details request.

### Preauthorization Transaction flow (Preauthorization + Clearing)

- Send create order request (Order_DMS). If success response go to step 2

- Redirect to URL with values from Create Order response (point 1): Url Sample: 

{{order.hppUrl}}/flex?id={{order.id}}&password={{order.password}}

- Redirect client with several (described below) transaction fields to redirect (callback ) url after transaction completion on PC (Processing center side). preauthorization first step completed and amount will be in hold. 

- When the service or product has been provided, you need to send a Execution Transaction Clearing request (Second step of preauthorization transaction). Transaction flow is completed

### Recurrent payment flow (no cvv2 and no 3d checks)

- Send recurrent payment create order (Recurring) request. If success response go to step 2

- Send Set Source Token request. If success response go to step 3

- Send Execute transaction (Purchase with saved card). If success response, transaction completed

### Order Credit Transaction flow (Send funds to card)

- Send recurrent payment create order (Order Credit Transaction) request. If success response go to step 2

- Send Set Destination Token request. If success response go to step 3

- Send Execute Transaction request (Execute Credit Operation). If success response, transaction completed

## Create Order

### URI

POST /order

This endpoint allows you to create a new order.

### Request

Returns a JSON object with the following properties:

- typeRid: Type of the order. List of order types

  - Order_SMS: For purchase operations

  - Order_DMS: For Preauthorization operations

  - Order_REC: For recurring Purchase operations (transactions with saved card)

  - DMSN3D: For recurring Preauthorization operations (transactions with saved card)

  - OCT: For Account-to-Card operations (Order Credit Transaction)

- amount: The amount associated with the order.

- currency: The currency used for the order.

- language: The language preference for the order.

- description: A brief description or comment about the order.

  - For Installment operations you must to send taksit month in description filed in this  format:TAKSIT=6

- hppRedirectUrl: The URL to redirect to after finishing operation.

- hppCofCapturePurposes: An array containing the purpose of capturing the Card-on-File (COF) for the order in Payment page (Card Save). Use all 3 data when saving.

- aut: Used with hppCofCapturePurpose. When specifying this parameter, the checkbox to save the card on the payment page will always be true

- srcToken.storedId: this parameter used to establish a payment token (Saved Card)

### Response

- id: The unique identifier for the order.

- hppUrl: The URL for accessing the Hosted Payment Page (HPP) associated with the order.

- password: A password or authentication token associated with the order.

- status: The current status of the order, which could be "Preparing" or any other status.

- cvv2AuthStatus: CVV2 authentication requirement for the order.

- secret: A secret or additional security information associated with the order.

## Execution Transaction

This request Is used for finalizing transaction

### URI

POST /order/{ID}/exec-tran

### Request

- phase indicator of transaction phase. phase examples:

  - Single. For one step operations (Standart Purchase)

  - Auth. For first step of preauthorization transaction. Must used with authorizationKind

  - Clearing. For the second step of preauthorization transaction.

- type Type of the operation. types example:

  - Credit. For Account-to-Card transaction

  - Refund. For send money for transaction back.

- amountThe amount to be authorized for the transaction. If it is not specified, amount will be used from Create Order Request

- authorizationKind  Must be used with Auth phase in preauthorization transaction

- conditions.cofUsage Indicator of recurring transaction.

```
{  
    "tran":{
        "phase":"Auth",
        "type":"Credit",
        "amount":"1.00",
        "authorizationKind": "Preliminary",
        "conditions":{
            "cofUsage":"Recurring"
        }
    }
}
```

### Example

Request

```
{
    "tran":{
        "phase":"Clearing",
        "amount":"1.00"
    }
```

## Reversal

This request used to cancel operation during the day

### URI

POST /order/{ID}/exec-tran

### Request

Request is the same as Execute Transaction request, but with the different params

- phase indicator of transaction phase. phase examples:

  - Single. For one step operations (Standart Purchase)

  - Auth. For first step of preauthorization transaction. Must used with authorizationKind

  - Clearing. For the second step of preauthorization transaction.

- voidKind Indicator of Revesal operation. Reversal types:

  - Full. Using for returning full amount of transaction

  - Partial. used to return funds that are less than the original amount. Can be used once

- amountThe amount to be returned for the transaction. Must be used, when you want to use Partial reversal.

```
{
    "tran":{
        "phase":"Single",
        "amount":"1.00",
        "voidKind": "Partial"
    }
}
```

### Example

Request

Full reversal after purchase

```
{
    "tran":{
        "phase":"Single",
        "voidKind": "Full"
    }
}
```

Partial reversal after purchase

```
{
    "tran":{
        "phase":"Single",
        "amount":"1.00",
        "voidKind": "Partial"
    }
}
```

Full reversal after preauthorization (after First step)

```
{
    "tran":{
        "phase":"Auth",
        "voidKind": "Full"
    }
}
```

Full reversal after preauthorization clearing (after second step)

```
{
    "tran":{
        "phase":"Clearing",
        "voidKind": "Full"
    }
}
```

## Payment Statuses

Status | Description

Being prepared | Order is being prepared, no transactions have been executed on it yet.

Cancelled | Order has been cancelled by the consumer (before payment). (Order is cancelled by the merchant.)

Rejected | Order has been rejected by the PSP (before payment). (Order is rejected by the PSP.)

Refused | Consumer has refused to pay for the order (before payment or after unsuccessful payment attempt). (Order is refused by the consumer.)

Expired | Order has expired (before payment). (Timeout occurs when executing the order scenario.)

Authorized | Order has been authorized.(Authorization transaction is executed.)

Partially paid | Order has been partially paid. (Clearing transaction is executed for the part of the order amount.)

Fully paid | Order has been fully paid. (Clearing transaction is executed for the full order amount (or several clearing transactions).)

Funded | Order has been funded (debit transaction has been executed). The status can be assigned only to the order of the DualStep Transfer Order class.

Declined | * AReq and RReq (3DS 2) could not be executed due to rejection by the issuer / error during authentication.

* Operation was declined by PMO

Voided | Authorized payment amount under the order is zero.

Refunded | Accounted payment amount and the accounted refund amount under the order are equal.

Closed | Order has been closed (after payment)
